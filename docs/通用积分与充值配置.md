# 通用积分与充值配置

2026-10-23。积分属于商城账号，所有设置为“按积分”的工具共用一个余额，每个工具独立配置成功处理一次所消耗的积分。原有免费、按次、包天 / 周 / 月 / 年和长期套餐继续兼容。

## 升级顺序

1. 先在应用实际连接的 MySQL 数据库执行完整的 `sql/07_shared_points_20261023174713.sql`，前置为既有商城、02 / 03 工具套餐和 06 印章迁移。执行前备份。不要用旧整库备份覆盖业务库。
2. 07 增加工具积分价格、充值订单积分快照、钱包及积分流水；为现有用户一次性赠送 100 积分，新增四档套餐、空的收款码配置和“积分管理”菜单。可重复执行，保留已有余额、充值 / 消费记录及管理员改过的套餐配置。
3. 更新代码并构建、重启应用。**公开工具查询也读取新的积分字段，所以 07 必须先于新版应用上线。** 新库的基础建表脚本已包含积分结构，仍需执行 07 初始化套餐和菜单。
4. 管理端 → 积分管理 → 充值套餐，逐个编辑套餐，上传与金额匹配的微信 / 支付宝收款码并启用。没有有效收款码的套餐前台不能购买。
5. 工具服务 → 编辑工具 → 收费方式选择“按积分（全工具通用）”，填写正整数消耗值；也可从原“通用套餐”的周期选择“按积分”切换。已有工具不会被 SQL 自动改为收费，工具消耗值由管理员决定。

助手未执行 SQL、切换工具收费状态或配置真实收款码，也未写入业务数据库。代码检查使用隔离数据库模拟，实际调试由用户完成。

## 前后台业务流程

- 首页账号区及共用导航增加“我的积分”入口，账户页 `/points` 展示余额、四档套餐和积分明细。未登录引导首页真实验证码登录后返回积分中心。
- 老用户执行 07 时领取 100 积分；新用户登录时初始化钱包。读取账户或首次使用积分也可补初始化。用户主键和 `welcome:<用户ID>` 操作号保证重复登录 / 读取 / 重跑迁移不会重复赠送。
- 用户选择套餐，服务端按当前套餐读取金额及积分，订单保存积分快照；前端传来的金额、积分或身份不参与计算。收银台展示本订单的金额与到账积分，改套餐不影响已有订单。
- 沿用现有微信 / 支付宝转账二维码和**管理员人工收款核验**。点击“我已完成支付”只查询核验结果，不会自行加积分。后台“积分管理 → 充值订单”核验到账；普通订单管理修改为已支付 / 已发货，或已验证的邮件回复，也调用相同到账事务。
- 充值核验锁定用户和订单，余额更新、流水及订单完成在同一事务内提交，订单最终显示“已到账”。重复核验和邮件重试只到账一次。已经到账的订单不能直接改回待支付 / 作废，也不能据此删除账务记录；本轮没有新增退款 / 人工调账功能。
- “用户积分”“积分流水”“充值订单”后台列表，以及账户积分明细，每页 20 条；后台按手机号筛选。积分管理有独立菜单权限，普通账号不能读取其他用户余额和流水。

## 印章与已有会员兼容

`stamp-maker` 已直接接入通用积分。成功生成成品后，在同一事务中复核权益、扣分、记录流水并保存成品；保存或渲染失败不扣分。

优先顺序为本工具有效时长 / 长期会员 → 本工具剩余次数 → 通用积分。已有订单按原周期和核验时间计算，不因为改成积分收费而失效。旧会员不跨工具共享，积分余额才在工具之间共享。

预览、刷新、打开工具、恢复历史成品和重复下载不扣分。同一任务重试恢复已保存成品；即使余额已耗尽，也不会重复收费。修改参数后重新成功制作属于新任务。并发使用最后一份积分时只允许足额的任务成功，余额不会透支。

## 外部工具接入

其他工具目前没有本仓库内的实际处理引擎。现已提供通用积分成功回调；**外部处理端必须完成接入后再开放积分使用，仅填写一个普通网页链接不会自动计费或保护该网页。** 内置印章不需要此配置。

1. 在商城服务端环境配置 `TOOLS_USAGE_SECRET`，使用至少 32 字符的随机密钥；相同密钥只交给可信工具服务端，禁止放到浏览器脚本或公开页面。示例环境文件预留该配置，留空时外部积分工具入口返回未配置提示。
2. 用户从工具介绍页进入时，`GET /api/tools/access?slug=<工具标识>` 检查真实账号、已有权益 / 积分，向工具链接添加签名参数 `yx_ticket`。签名绑定用户、工具、价格、唯一任务号和 2 小时有效期；**此时不扣分**。
3. 工具处理端校验任务凭据并确保同一凭据最多执行一个处理任务。失败时不调用成功扣费；可用 `success:false` 回报失败，不会扣分。
4. 成功生成结果后，由工具服务端向商城发送 `POST /api/tools/usage`，请求头 `x-tool-usage-secret: <服务端密钥>`，JSON 为 `{"ticket":"原始 yx_ticket","success":true}`。前端不得持有密钥或直接发起可信成功回调。
5. 只有商城返回 200 / `ok:true` 后才向用户交付处理结果。响应包含 `charged`、`duplicate`、`pointsSpent` 等；旧按次权益可能扣次而不扣积分。网络不确定时重试相同凭据，同任务不会重扣。余额不足返回 402、配置变化 409、签名 / 超时无效 401，不得在这些情况下直接交付收费结果。
6. 一个凭据对应一个任务；下一个处理任务重新从商城授权接口取得新凭据。外部服务自身必须保护直接访问路径、验证凭据、保持任务和结果幂等，避免绕过商城直接调用处理引擎。可先以 `success:false` 调用商城验证签名且不扣费。实际处理超过凭据有效期的任务需要重新规划授权时限后再接入。

商城回调会再次复核工具启用状态和价格、优先使用当前有效旧权益，并在事务中完成扣次 / 扣分和唯一操作流水；其他工具不能借用此凭据扣费。外部服务接入与其处理引擎实现仍是各工具开发范围，不将接口准备完成等同于四个工具引擎都已实现。
