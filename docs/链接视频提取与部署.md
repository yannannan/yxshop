# 链接视频提取工具（2026-10-24）

## 页面和业务

- 独立地址 `/tools/video-extractor.html`，固定页面标识 `video-extractor`，保留商城导航、面包屑、服务端正文、SEO 标题、canonical 和结构化数据。
- 页面按“粘贴链接 → 选择画质 → 提取下载”操作，支持完整分享文字、剪贴板粘贴、真实画质和文件格式、处理进度、成品预览与下载、本人历史记录（每页 5 条）。手机布局自动单列。
- 工具介绍 / 操作页面可免登录进入；解析与提取需要真实登录，避免匿名占用下载和存储资源。免费模式也需要登录，以便隔离历史和成品，登录后自动回到视频工具。整页 500 不属于登录拦截，本次 ipaddr.js 缺失排查见 [Linux 页面 500 与工具访问](Linux页面500与工具访问排查.md)。
- 后台“工具服务”编辑此工具：免费 / 收费 / 按积分 / 待确认，沿用已有套餐分类、按次、包天、包周、包月、包年及长期权益；按积分时填写每次成功提取消耗值，充值与收款码在积分管理维护。
- 本次不会替用户修改已有收费方式、价格、状态、会员、积分余额和充值套餐。原记录若仍是“待确认”，可以解析，但不能提取；请管理员自行确认开放方式。
- 有效时长会员优先，其次已有本工具次数，最后通用积分。权益在开始前预检，文件完整保存后再次在事务内复核，扣次 / 扣积分与任务完成一起提交。收费配置变化、下载或合并失败、余额不足时不发放成品且不扣费。
- 同一任务 ID + 解析结果 + 画质重试返回同一任务；同任务重复完成和下载不再扣费。修改画质并重新提取是新任务。任务归属由真实会话决定，不采用前端提供的用户、价格或积分值。
- 充值和工具套餐继续走原二维码支付核验流程，不是自动支付网关。业务数据库及真实收费整单未由助手操作或验收。

## 实际支持边界

采用“平台 / 公开页面解析 → yt-dlp 默认及通用规则 → 后端动态网页解析”的组合，返回的标题、时长、画质和媒体源均来自实际结果。原来的少数平台白名单不再限制通用解析；除抖音、小红书、B站、Facebook、YouTube 等，还会尝试当前 yt-dlp 版本提供规则的其他站点和普通网页。不同规则及动态引擎相互兜底，具体链接仍需要源站提供公开可读取的媒体。

- 快手先读取公开分享页的 HTML5 / OG 视频源和 JSON 状态（Apollo / Initial State / Next Data），按当前视频 ID 选择媒体；无可用源时再尝试通用规则及动态网页引擎，不将不存在的原生规则当作已支持。
- 好看视频读取 `__PRELOADED_STATE__.curVideoMeta` 与真实 `clarityUrl`，按画质验证媒体。用户提供的 `vid=6658134627915427060` 已在本轮通过应用下载为 3,948,534 字节 MP4，并检查视频和音频可解码。
- 抖音支持整段分享文字中的 `https\://` 转义写法和移动短链。先尝试公开状态，必要时通过项目内 Chromium 的全新匿名上下文访问作品，获取站点正常下发的访客会话及匹配作品的详情；不读取用户现有浏览器或登录 Cookie。最多允许一次访客上下文刷新，再回退原生规则。只有作品编号匹配的数据可用于下载，不把推荐流的视频混入结果。
- **抖音公开作品已实际下载成功**：`7692515320217407402`（“如果现在是2026年”，4.934 秒）通过匿名网页解析及应用下载生成 1,618,547 字节 MP4，视频 / 音频解码检查通过。用户原短链 `hpy7HCcu6IY` 对应作品 `7421576130160905483`，新引擎正常读到 `filter_reason=status_friend_see`，源站明确为“仅好友可见”；页面会准确提示权限限制，不再误报成通用的登录 / 不支持错误。没有进行私密内容提取。
- 直链支持 MP4 / WebM / MOV；B站等分离音视频在本地经 FFmpeg 合并。未加密的 M3U8 / HLS 点播支持主列表画质、独立音轨、TS / fMP4 分段、初始化分段和字节范围，逐段经公网检查下载后只把本地媒体交给 FFmpeg 转为 MP4。缺少合并组件时明确提示。
- 源站可能要求登录、Cookie、地区验证、反机器人验证，或更改规则。没有真实平台链接验收前不能保证每个链接都成功；页面会明确提示失败，解析失败不扣费。当前不导入浏览器 Cookie，不绕过登录、DRM 或其他访问限制，不去水印。
- 普通网页优先读取公开 HTML5 `video/source`、Open Graph、JSON-LD、平台 iframe，失败后尝试通用规则和匿名动态网页引擎，从媒体请求、响应类型与 video 元素中寻找真实地址。浏览器里的 blob 地址本身不能直接粘贴，需复制原网页 URL。Chrome、Edge、Firefox 等浏览器复制来的 URL 都可尝试。
- 动态解析在独立匿名浏览器进程中执行页面正常脚本并加载站点 SDK，不在 Node 进程中 eval 网页代码，不使用用户已有浏览器数据。并非浏览器扩展，也不承诺每个动态页面都成功。DRM、加密播放列表、需授权的私密 / 好友内容、直播、整份合集及独立 DASH MPD 分段暂不支持；平台返回独立 HTTP(S) 音视频文件时可合并。
- 平台元数据超过 60 分钟的视频拒绝解析。普通直链没有可信时长时仅按大小限制，不承诺提前获知时长。画质以实际可读取的结果为准，单个预览最多 12 个选项。
- 用户应只保存有权使用的内容。

官方依赖说明：[yt-dlp README](https://github.com/yt-dlp/yt-dlp#readme)、[发行文件](https://github.com/yt-dlp/yt-dlp/releases/latest)、[FFmpeg 下载](https://ffmpeg.org/download.html)、[Playwright Chromium](https://playwright.dev/docs/browsers)。规则及引擎需随平台变化维护。

## 首次部署

**CentOS 7 / Stream 9/10 x86_64 原生部署：**先同步本轮代码，在项目目录执行 `bash scripts/install-video-deps-centos.sh`，一次准备系统库、官方 yt-dlp、当前系统兼容的 FFmpeg 和 Firefox / BiDi 动态解析引擎，并实际检查浏览器启动。不安装 Docker，不修改数据库、Nginx 或商城启停。详见 [CentOS 视频提取依赖安装](CentOS视频提取依赖安装.md)。下面的通用 Chromium 安装方式不用于 CentOS 7。

在项目根目录操作。现有站点先执行前置工具 / 积分迁移，再只新增执行：

`sql/08_video_extractor_20261024003237.sql`

前置为 `02`、`03`、`06`、`07` 对应迁移，已经执行的不需要盲目重跑。08 可重复执行，创建解析预览 / 提取任务两张表，只补齐视频工具的空入口，不改变业务收费数据。不要用根目录旧整库备份覆盖业务库。新建数据库的 `scripts/mysql-init.mjs` 已同步两张表。

安装平台解析引擎：

```sh
node scripts/setup-video-engine.mjs
```

脚本仅下载 yt-dlp 官方 GitHub 发布的当前版本，并验证同一发行版本的 SHA256 后放进项目 `vendor/video-engine/`，不修改系统 Git、Python 或 yum 源。支持 Windows x64 / ARM64、Linux x64 / ARM64 和 macOS。Linux x64 使用独立 `yt-dlp_linux`，不依赖系统旧 Python。网络不能连接 GitHub 时可手动下载相同发行版本的独立文件和校验清单，校验后放置到默认位置。

安装后端动态网页引擎（抖音需要）：

```sh
pnpm install --frozen-lockfile
node scripts/setup-video-engine.mjs --browser
```

该命令使用锁定的 `playwright-core` 官方安装程序，只下载 Chromium Headless Shell 到项目 `vendor/video-engine/browser/`，并记录当前机器的可执行路径。运行时和匿名上下文不提交 Git；每台服务器需要单独安装，不能照搬 Windows 的路径记录。`VIDEO_BROWSER_PATH` 可指定兼容的已有引擎，`VIDEO_BROWSER_ENABLED=0` 可禁用动态兜底。

Linux 的 Chromium 路线仍需兼容系统库及非 root 服务账号。CentOS 7 不在当前 Playwright 支持的系统列表内，因此新增独立安装脚本改用官方 Firefox / BiDi；不再把它与 Chromium 的系统要求混用，也不要求 Docker。助手未连接服务器执行安装，须以实际启动自检通过为准。系统范围见 [Playwright 官方要求](https://playwright.dev/docs/intro#system-requirements) 与 [CentOS 安装步骤](CentOS视频提取依赖安装.md)。

默认文件：

| 系统 | 平台解析 | 音视频合并 |
| --- | --- | --- |
| Windows | `vendor/video-engine/yt-dlp.exe` | `vendor/video-engine/ffmpeg.exe` |
| Linux / macOS | `vendor/video-engine/yt-dlp` | `vendor/video-engine/ffmpeg` |

**为支持 B站等分离音视频，必须准备兼容系统的 FFmpeg。** Windows x64 可显式执行 `node scripts/setup-video-engine.mjs --ffmpeg`，从 [FFmpeg 官网](https://ffmpeg.org/download.html) 链接的 [Gyan 构建发布页](https://www.gyan.dev/ffmpeg/builds/) 下载 Essentials ZIP，核验发布者 SHA256 后只提取 `ffmpeg.exe` 到项目目录，不修改系统 PATH。Linux / macOS 等系统从官方链接选择可信的系统包或构建，把可执行文件放在上表位置，或指定已有路径。Linux 文件需要具备执行权限；不要设置 777。无需把二进制提交到 Git。

在本地环境文件 / 服务器 `.env.mysql` 中可以配置：

```dotenv
# 留空时使用上表默认路径，也可以填相对项目目录或绝对路径。
VIDEO_YTDLP_PATH=
VIDEO_FFMPEG_PATH=/usr/bin/ffmpeg
VIDEO_BROWSER_PATH=
VIDEO_BROWSER_ENABLED=1
VIDEO_MAX_FILE_MB=200
```

`/usr/bin/ffmpeg` 只是示例，必须填写实际安装路径；Windows 可使用 `D:/.../ffmpeg.exe`。本地启动命令也要加载对应环境文件。项目已有 Node 运行时用于 yt-dlp 的 JavaScript 运行支持，不额外启用远程组件、用户插件或用户配置。

检查安装（不解析真实视频、不连接业务数据库）：

```sh
node --env-file=.env.mysql scripts/setup-video-engine.mjs --check
```

之后按原项目流程构建并启动；本轮新增 `playwright-core`，npm / pnpm 锁文件均已同步。本轮扩大解析能力无需新增 SQL，已有 08 迁移保持有效：

```sh
pnpm install --frozen-lockfile
pnpm build
./start.sh
```

默认运行于长期存活的 Node 服务，提取 POST 很快返回任务编号，页面轮询 GET；不需要为提取任务把 Nginx 请求等待时间改为数分钟。排队任务访问本人记录时可恢复；进程重启导致中断的处理任务会在超时后标失败，不扣费，需要重新提取。当前不支持跨多台服务器分发任务；多实例部署需共享持久存储及单独任务调度器后再扩展。

## 存储、限额与访问

- 私有文件保存在项目根目录 `uploads/video-extractions/<任务UUID>/result.<格式>`，不是 `public/`。该目录与引擎二进制均已忽略 Git，升级时应保留。不要在 Nginx 暴露这个私有目录为静态下载。
- 每个文件保留 24 小时；解析预览有效 15 分钟，过期可重新解析。成品下载需登录且属于当前用户，支持 Range 播放和重复下载。源站签名媒体地址与请求头仅保留在服务端，不向普通 API 客户端输出。
- 默认下载总量最多 200 MB，可配置 20–1024 MB。全进程最多同时提取 2 个任务，每人最多 2 个排队 / 处理任务。
- 每人成功解析每小时最多 30 条；进程内失败尝试也计入限流、每人最多同时解析 2 条，全进程最多 8 条。生产中应按实际流量另配网关限速。
- 每次提取后尝试清理固定目录中超龄 UUID 目录（每次至多 100 个），同时删除过期解析记录；保留任务历史。无新任务时清理不自动触发，仍需关注磁盘容量。
- HTTP 资源、封面和重定向使用公有 IP 校验和固定 DNS 连接，禁止本地 / 内网 / 保留地址；不转发用户 Cookie 或授权头。yt-dlp 的默认 / 通用规则与动态引擎统一走仅回环地址、随机凭据的临时代理；每次 HTTP / CONNECT 重新检查目标并固定公网 IP，只允许 HTTP 80 / HTTPS 443，拦截本机、私网和保留地址。代理每次解析限制 400 次请求、48MB 下行及 8MB 上行，关闭时销毁连接。禁用用户插件、远程组件和配置文件；Chromium 保持沙箱、禁用服务工作线程及直接 UDP，匿名上下文、浏览器和代理在结束后关闭。
- 动态引擎全进程最多同时运行 2 个，不共用账号或浏览器用户数据；默认一次约 24 秒预算。HLS 最多 1200 个分段、总时长 60 分钟，拒绝加密和直播，逐个检查资源地址及 Range 响应，不把远程播放清单交给 FFmpeg。
- 系统 DNS 将公网域名解析成代理 / 私网地址或解析失败时，先向固定的阿里 DNS / Cloudflare HTTPS DNS 复核，再固定到经验证的真实公网 IP，不能直接连接系统返回的内网地址。校验问题域名、CNAME 链、全部 A 记录和响应大小；同域名并发复用查询，按 DNS TTL 最多缓存 60 秒。真正的内网 IP、本地域名、私网混合结果仍被拒绝；复核失败时提示 DNS / 代理异常。参考 [Cloudflare DNS JSON 协议](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)。
- 商品图片读取接口同时收紧为 `products/<图片文件>`，不能通过 `products/../` 读取私有视频或其他项目文件。

## 代码检查与验收

自动回归使用模拟网络 / 平台 / MySQL 和项目内临时文件，覆盖积分与次数并发、回滚、幂等、权限、匿名引擎清理、代理拦截、HLS、下载鉴权与 Range。已安装项目 FFmpeg 时还会生成离线音视频及 HLS，实际经应用合并 / 转封装后验证音画解码；未安装时仅跳过二进制集成检查。本轮 200 项通过，生产构建及修改文件 ESLint 通过，全项目仍为原有 20 处类型错误。

```sh
node --experimental-strip-types --test tests/*.test.mjs
```

后端真实链接检查无需运行商城、连接数据库或扣积分：

```sh
node scripts/check-video-link.mjs "公开视频分享链接"
node scripts/check-video-link.mjs "公开视频分享链接" --download
```

命令行检查使用开发依赖 TypeScript，需安装完整项目依赖；输出只展示标题、公开画质信息和本地成品路径，不打印签名媒体地址或匿名会话。`--download` 文件保存至新的 UUID 私有目录，检查工具不创建订单或业务记录。

本轮通过该后端流程实际提取了抖音公开作品、用户的 B站 `BV1AMDvBaEY6`（生成带音轨的 1,741,468 字节 MP4）和好看视频；三者均通过音画解码检查。读取了用户抖音原链接的好友权限限制。未启动商城服务或进行商城 UI 浏览器核查，未操作真实收费、业务数据库或服务器。其他平台没有逐一实测，不把通用规则可尝试表述为每条链接必定成功。
