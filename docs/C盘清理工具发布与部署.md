# C盘清理工具：宣传页与软件发布

工具服务中的 C盘清理工具现进入 `/tools/c-drive-cleaner.html` 独立产品页面，使用自己的导航、宣传首屏、功能介绍、截图、版本更新、下载区和常见问题。布局参考 [360 官方产品页](https://weishi.360.cn/product.html) 的产品介绍与下载结构，使用宇星脉通自己的品牌、样式和内容。

当前按“免费、无需登录下载”实现，不创建订单、不扣积分。页面兼容中英文与移动端；软件运行于后台填写的 Windows 系统，网页访问本身不执行清理。用户提供的六张临时截图本轮均无法读取，因此没有编造软件截图、版本、支持系统或清理效果。未配置截图时显示原创磁盘示意图，未发布安装包时明确显示“版本即将发布”。

## 首次部署

1. 同步完整代码，按既有方式构建并启动。没有新增依赖，`upgrade.sh` 与迁移脚本本轮未改。
2. 在商城业务 MySQL 库执行 `sql/16_software_releases_20261112.sql`。前置为已存在工具产品字段的 02 号增量；16 号仅新建两张表，可重复执行，不修改现有商品、积分或发布记录。本轮开发未执行真实数据库 SQL。
3. 确认 `c-drive-cleaner` 工具已启用，收费方式为“免费使用”。若存在其他同名旧工具，维护页面标识为 `c-drive-cleaner` 的这一条。
4. 配置下述 OSS 存储。环境配置变动后重启商城进程。
5. 管理端 → 工具服务 → C盘清理工具 → **软件发布**。此入口和所有写入接口要求工具管理权限。

两张新增表分别存放产品介绍 / 截图，以及安装包版本 / 发布状态 / 文件摘要 / 下载请求次数。不存储用户电脑文件，不执行上传的软件。缺少 16 号表时，前台仍可显示待发布宣传页，后台提示初始化。

## 维护产品介绍与截图

在“宣传内容与截图”中填写宣传标题、产品说明、实际功能，最多 8 项功能、8 张截图。可选填对应英文内容，未填英文时沿用中文。截图支持 8MB 内 PNG、JPG、WebP，上传后还需点击“保存产品介绍与截图”。第一张用于首屏，其余图片可在界面预览区切换；支持前移和移除。

截图沿用商城商品图片服务，保存在现有 `UPLOAD_DIR/products`（默认项目 `uploads/products`）；迁移服务器时必须同时迁移该目录。图片从介绍中移除不会自动删除磁盘文件。

## 发布 EXE

1. “版本发布”填写版本号、支持的 Windows 系统、更新说明，创建草稿。
2. 在该草稿行上传 EXE，最大 **256MB**。显示上传进度，上传完毕还会校验；只有校验保存成功后才可发布。
3. 核对文件名、大小和 SHA256，点击“发布”。发布后前台提供最新版本的匿名免费下载。
4. 发布新版本自动将原当前版本下架；历史已发布版本的说明仍会展示（最近 5 条）。后台可将已下架版本重新设为当前版本。草稿可改说明 / 替换 EXE，已发布版本不可直接换包。
5. 点击“下架”停止签发该版本的新下载地址，原已签发地址最多还可有效 5 分钟。停用工具或改为收费也会关闭免费签发。

后台展示最近 50 条版本。下载请求数是成功签发下载地址的次数，**不是下载完成次数、独立用户数或安装人数**。工具管理“使用统计”继续记录页面访问和软件下载点击；桌面软件实际使用情况不在本轮范围内。

## OSS 与上传限制

`SOFTWARE_OSS_*` 凭据全留空时复用现有 `VIDEO_OSS_BUCKET / REGION / ACCESS_KEY_ID / ACCESS_KEY_SECRET / STS_TOKEN`。需要独立凭据时按 `.env.mysql.example` 填完整 `SOFTWARE_OSS_*` 组，不混用两组中的部分字段。密钥只放服务器环境文件，不进入前端或 Git。

- 安装包使用私有对象，固定前缀：`yxshop/software-releases/c-drive-cleaner/`，每次上传生成独立对象名。
- 该前缀应长期保留，不要套用签署文件的到期删除规则。凭据需要此范围的上传、读取 / HEAD、删除与设置私有对象 ACL 的权限。
- 默认通过公网 HTTPS 上传和下载；阿里云同地域服务器可设置 `SOFTWARE_OSS_INTERNAL_UPLOAD=1` 使用内网上传 / 校验，签发给用户的地址仍为公网 HTTPS。
- 上传先流式落到项目 `uploads/software-staging` 的私有临时目录，计算 SHA256 / MD5，检查 Windows EXE 的 MZ / PE 头，上传后 HEAD 核验大小和摘要。该检查不等于数字签名认证或杀毒扫描。临时文件在操作结束时清理，需预留每个并发上传最多 256MB 的磁盘空间和目录写权限。
- 上传失败保留原草稿安装包；替换成功后再清理旧草稿对象。数据库提交状态不明时保留新私有对象，避免误删已提交文件。异常遗留对象暂不做全目录自动删除。
- 反向代理若限制请求体，需允许 EXE 上传，例如 Nginx 对上传路由设置 `client_max_body_size 260m;`，并合理设置上传与代理等待时间。浏览器本次上传等待上限为 660 秒；上传超时后先刷新版本列表确认结果。部署方按实际代理配置调整，本轮未修改 Nginx。

下载由服务端核验工具与版本状态、HEAD 校验文件后签发 5 分钟 OSS V4 附件地址。响应头在上传对象时设置，签名时不叠加响应头覆盖参数，避免此前 OSS 的响应头覆盖错误。前台失败时显示可重试回执，不伪装成下载成功。

107 项相关回归、13 项生产处理器检查、生产构建、修改文件 ESLint、CSS 解析与差异空白检查通过。覆盖管理员 / 同源限制、草稿不可公开、上传与发布分离、上下架、事务回滚、失败保留原文件、离线真实 OSS SDK 上传参数和 V4 签名、中英文宣传页及下载按钮回执。测试使用内存 SQLite、模拟云传输和项目内临时文件，不监听端口、打开浏览器或连接真实业务库 / OSS。
