# 站长分析综合看板（2026-10-25）

## 本轮范围

按用户选择的第一个导航设计落地：保留全站顶部导航，左侧 SEO 工作台，右侧综合看板。桌面为双栏，移动端侧栏变为可横向滚动的导航。

已实现的流程：登录用户选择或输入域名 → 确认分析范围 → 创建持久任务 → 后台分步采集 → 生成报告 → 保存历史 → 后续打开同一报告。页面刷新、查看记录、导出报告均不重复创建任务或收费。

- 网站档案：当前 DNS / IP、CNAME、域名服务器、RDAP 公开注册资料、网站标题 / 描述 / 语言、行业推测、HTTP / HTTPS、网站自行声明的关键词。
- 页面和关键词：首页、同源站内链接、最多三份站点地图；每轮选择 5 / 20 / 50 个页面，最多发现 1000 个地址，最多保留 200 个关键词候选。来源可展开查看，支持来源 / 文字筛选和分页。
- 搜索引擎：百度与 Bing 的公开结果适配器；**默认不启用搜索查询**，用户可勾选。本轮取前五个候选词、前十条自然结果。遵守 robots 规则；验证码、受限、结果不足、落地地址无法核实均明确显示，不视为无排名。Google 为“尚未接入可用数据来源”，不接受启用请求。
- 报告与历史：分步进度、完整 / 部分 / 失败状态，按相同分析条件比较历史候选词与成功排名记录；网页历史、JSON 下载、打印；个人中心 → 工具记录 → 站长分析可返回实际工具 slug 的报告。
- 运营事项：已采集页面的 HTTP 错误、缺失 / 重复标题、缺失描述、noindex、动态渲染失败。可以标记待处理 / 已处理 / 已忽略；处理标记单独保存，不覆盖原始报告快照。
- 前台中英文共用既有语言框架；采集到的标题 / 关键词等业务原文不翻译。后台继续中文。

关键词挖掘、搜索排名、竞品对比的独立工作区仍待逐个设计，左侧标为筹备中。当前竞品区明确说明未接入，没有演示排名、流量、搜索量或竞品数据。第一版只执行用户主动创建的分析任务，没有自动定时采集计划、免费 Search Console 授权或 PDF / Excel 文件导出服务。

## 数据和采集口径

输入含路径的 URL 时，以该 URL 的域名首页为分析起点；保留 http / https 和主机名，www 与裸域只在本次公开跳转中兼容，不擅自采集其他子域名。

1. DNS 和 RDAP 分别获取；注册主体不公开时显示未公开，获取失败显示不可用。域名注册时间不等同网站上线时间。RDAP 从 IANA bootstrap 选择对应权威服务，不采集第三方 SEO 站的付费数据。
2. 读取 robots，普通 HTTP 解析优先；仅当首页为缺少文本的脚本页面时尝试匿名浏览器渲染。复用既有浏览器二进制 / 公网代理设计，不修改视频代码或再次安装浏览器。失败保留静态信息并提示内容不完整。
3. 请求固定至经校验的公网 IP；每次跳转重新校验。页面有超时、跳转、解压后大小和同源范围限制，脚本渲染禁止下载文件。按 robots 的延迟要求逐站访问。
4. 关键词先提取 / 去重 / 过滤，用户词和网站声明词保留来源；没有真实来源的搜索量、流量和所谓官方权重不生成。排名记录仅表示本次采集节点观察到的前十条结果，不代表所有地区或全网关键词。
5. 全轮采集预算三分钟。临时数据在运行内存，浏览器匿名档案在结束时清理；结构化报告存 MySQL，浏览器 JSON 下载直接生成 Blob。本轮没有长期本地 HTML 文件，也不要求新增 OSS 密钥；未来文件报告可复用现有 OSS 配置。

## 任务和扣费

- MySQL 队列持久化；独立 Node 采集进程每三秒查看队列，原子领取任务。租约 60 秒，每 10 秒续约，用 claim token 防止旧进程覆盖新结果；多个采集进程可竞争领取不同任务。
- 停服信号使未完成任务回到队列；强制退出遗留的运行任务在租约过期后恢复，最多三次中断尝试，随后标记失败。不会重复扣费。
- 所有读取 / 创建 / 标记使用已验证签名会话和活跃用户身份，不接受客户端 userId。报告、站点和记录仅本人可读。
- 写操作校验来源，兼容现有 Nginx 传递原 Host 和 X-Forwarded-Proto 的 HTTPS 终止方式，不通过任意 X-Forwarded-Host 放行其他站点。
- 沿用已有工具的免费、积分、会员及次数配置；本 SQL 不设置价格或切换收费模式。完整成功报告优先用有效时长会员，再用次数，最后用积分。部分完成 / 失败不扣费。资料未公开属于正常缺省；数据源不可用则标记部分完成。
- 完整报告、规范化数据、扣次 / 积分流水在同一事务提交。工具配置或余额在采集期间变化时保留未扣费的部分报告；写库失败回滚，不产生扣费成功但无报告的状态。
- 创建任务的 UUID 与请求哈希保证重试幂等；同账号相同条件的活动任务复用。默认每人最多两个活动任务、每小时二十轮、一百个站点；单个进程串行领取，增加进程 / 服务器可以扩展工作量。

## 表结构

生产增量 SQL：`sql/10_site_analysis_20261025.sql`，只新增九张表并补齐已有站长工具的空入口；可重复执行，不删除数据、修改已有收费配置或新增商品。

| 表 | 用途和关键字段 |
| --- | --- |
| site_analysis_sites | 用户站点；id、user_id、host、url、创建 / 更新时间；唯一约束 user_id + host |
| site_analysis_runs | 队列与历史入口；用户 / 工具 / 站点、条件与价格快照、request_hash、状态 / 进度 / 阶段、attempts、claim_token、lease_until、draft_json、扣费与错误信息 |
| site_analysis_reports | 固定报告快照；run_id 主键、user_id、site_id、report_json、生成时间 |
| site_analysis_pages | 实际页面及采集依据；run_id + url_hash 主键、URL、页面 JSON |
| site_analysis_keywords | 候选词；run_id + word_hash 主键、关键词、来源类型、提取分数、来源页面 JSON；分数用于候选排序，不当作搜索量 |
| site_analysis_rankings | 引擎观测；run_id + engine + word_hash 主键、状态、可空位置、落地 URL、查询来源、时间及说明 |
| site_analysis_events | 阶段日志；任务、阶段、状态、消息和时间 |
| site_analysis_workers | 进程心跳，供工作台判断后台是否就绪 |
| site_analysis_issue_actions | 用户对单份报告事项的处理标记，与原报告分离 |

生产 DDL 使用 InnoDB、utf8mb4；域名转为 ASCII / Punycode 后保存，站点唯一索引兼容较旧的索引长度限制。关联和原子性由应用事务维护，不添加对既有业务表的外键。`db/schema.ts` 同步项目既有 Drizzle / SQLite 镜像定义；`scripts/mysql-init.mjs` 复用 10 号脚本的 CREATE TABLE，避免复制两套 MySQL 定义。

## 部署

助手没有连接真实数据库或执行本 SQL。

1. 将完整本轮源码同步到服务器实际使用的远程分支。GitHub main 与服务器自建 origin/master 分别同步。
2. **在应用当前连接的业务库执行 `sql/10_site_analysis_20261025.sql` 一次**。新建整套库的基础初始化脚本已包含建表，但不会自动创建站长商品。
3. 运行原 `bash upgrade.sh`，按锁安装新增 JS 包、构建并启动。原 upgrade.sh 内容不变；start.sh 一起启动站长采集进程，stop.sh 一起停止。日常升级无需重跑 SQL，不自动下载视频二进制或安装新浏览器。
4. 管理端确认已有“站长分析工具”已启用、收费配置正确；入口仍是原工具页面。支持既有名称为“站长分析工具”的商品，以及 webmaster-tools / webmaster-analysis / webmaster / site-analysis / site-analyzer / website-analysis 等 slug。保留已有 slug 和链接。
5. 进入工具，登录后用自己可访问的公开站点创建报告；检查历史回看、部分完成状态、积分和重复查看。

新服务器迁移继续用 `bash migration_upgrade.sh`；新增 `scripts/migrations/20-site-analysis.sh` 只检查锁文件中的业务包可加载，不连接数据库、不执行 SQL、不安装系统组件。既有 10-video-deps 步骤及视频迁移策略不变。

Windows 本地沿用原 `pnpm dev`。创建任务后，开发进程消费持久队列，读取排队记录时也能恢复处理；无需额外手动启动浏览器。生产关闭页面后由独立进程继续运行。
