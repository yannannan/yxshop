# 工具服务管理与统计

管理端「工具服务」分为「工具管理」「使用统计」两个页签，仅拥有工具管理权限的管理员可读取或维护，管理端保持中文。

## 手印制作

手印是文件在线签名的子功能，前台拥有独立入口。管理端现在将其单独列出，沿用原产品编号、套餐、用户手印库和制作记录，不创建重复产品或迁移用户数据。

- 「积分配置」仅修改手印制作的模块积分，留空使用文件签名的默认积分；不会连带修改制作签名、签署文件的价格或主工具收费方式。
- 「所属工具配置」维护文件签名的收费方式、套餐与收款配置。
- 「停用入口」隐藏独立手印入口；文件签名工作区中的手印功能仍按主工具权限使用。主工具停用后，其手印独立入口也不再公开。

## 排序

可填写排序数字，或清空搜索后使用上下按钮调整位置。点击「保存排序」后同步到前台公开工具列表。数字越小越靠前；相同数字按页面标识稳定排列。全部入口在同一事务保存，列表变化时须刷新后重排，写入失败整批回滚。

入口排序与产品原有排序分开保存，不改变普通商品顺序。手印可与其他工具独立排序。首页若配置了自定义工具展示顺序，仍以首页展示配置为准。

## 统计口径

- **入口点击**：首页 / 工具目录卡片及工具介绍的进入按钮点击。浏览器原生导航照常执行，上报失败不阻止打开。
- **页面访问**：工具页面打开及客户端路径切换；开发模式重复执行同一挂载效果不会重复记访问。
- **功能点击**：图片处理各功能、文件签名 / 签署 / 印章 / 手印菜单的实际切换，已选中项重复点击不计。
- **使用人数**：完成记录关联的登录账号去重。总人数从全部任务共同去重，不直接相加各功能人数；不代表实时在线人数。
- **完成次数**：已保存的签名、手印、图片、印章、签署成品、已就绪视频、已生成的完整或部分站点分析报告，以及可信成功结算记录。预览、失败、重复下载不计。匿名且未保存的制作没有成功记录，不计入此项。
- **消耗积分**：仅从 `points_ledger` 的真实消费流水读取。成品和流水按原计费操作号去重，已删除素材仍可由历史元数据 / 流水统计。免费、会员与按次权益完成次数可以增加，但积分消费仍为零。

手印从文件签名中单独归属，不重复累计。统计提供全部时间、今天、近7天、近30天，以北京时间自然日为边界。总览始终为全部工具，工具筛选影响下方明细表；点击工具名称可展开功能明细。

点击为浏览器上报数据，可能受拦截影响，从接入后开始累计，无法恢复过去未采集的点击。只保存事件、工具 / 功能、账号编号、随机会话哈希与服务器时间，不保存文件内容、URL 查询参数或 IP。客户端不能指定计费或覆盖登录身份；接口有同源检查、大小限制、会话频率限制及事件编号去重。

## 部署

1. 备份应用数据库，在应用 MySQL 8.x 库执行 [15号工具管理增量SQL](../sql/15_tool_management_20261111.sql)。可重复执行，不覆盖已有排序、积分、产品、用户或成品记录。
2. 同步完整代码并按原流程执行 `bash upgrade.sh`；新服务器仍按原迁移脚本准备业务环境。本轮没有修改升级脚本。
3. 管理端核对手印行和积分，调整顺序后保存，再访问前台检查。用测试账号完成一个任务，核对统计与积分流水。

新 SQL 只创建 `tool_entry_settings` 和 `tool_activity_events`。未执行时公开工具按原顺序运行，管理端可看到手印，但新排序 / 入口状态无法保存；统计显示已有业务记录并提示点击未启用。各工具自身的前置增量 SQL 仍按原部署要求执行。

新增工具默认支持入口和页面访问统计；新功能需在 `lib/tool-analytics.ts` 注册名称并在功能按钮上设置 `data-tool-slug` / `data-tool-module`。新工具的成功结果需加入 `lib/tool-analytics-service.ts` 数据源，复用真实计费操作号，避免把客户端点击当作成功使用。

本轮使用项目内隔离数据库与模拟请求检查，未连接业务数据库、执行真实 SQL、使用真实 OSS 或启动浏览器 / 服务。实际 MySQL 部署和界面效果需在部署环境验收。
