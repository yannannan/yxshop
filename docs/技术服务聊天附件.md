# 技术服务聊天与附件

客户侧在线技术支持、管理端“上门服务 → 在线咨询”、技术人员工作台共用消息与附件显示。客户侧自己的消息在右侧；管理端和技术人员侧回复在右侧，客户消息在左侧。原消息身份与历史内容不改动。

## 使用

- 输入框支持多行文字；Enter 换行，Ctrl / Command + Enter 或“发送”按钮发出消息。
- “图片”选择 PNG、JPG、GIF、WebP，可在聊天中预览并查看原图；“文件”可发送其他附件。每条消息支持一个附件，最大20MB，可同时填写说明，也可只发送附件。
- 失败时保留文字和所选附件，并显示失败原因。成功后刷新当前会话。打开聊天时每5秒更新消息，不强制拉走正在阅读历史消息的滚动位置。

## 配置与部署

本轮不新增 SQL 或 npm 依赖，复用现有 `technical_consultation_messages.content` TEXT 字段保存服务器生成的消息/附件记录，历史纯文字消息继续正常显示。按既有 `upgrade.sh` 流程同步完整代码、构建并启动。

附件配置在服务器 `.env.mysql` 中填写 `CHAT_OSS_BUCKET`、`CHAT_OSS_REGION`、`CHAT_OSS_ACCESS_KEY_ID`、`CHAT_OSS_ACCESS_KEY_SECRET`，临时凭据可填 `CHAT_OSS_STS_TOKEN`。整组留空时复用已有 `VIDEO_OSS_*` 配置；填写部分独立配置时不会混用两组密钥。客户端不会获得密钥或OSS对象路径。未配置附件存储时，纯文字聊天仍可用。

云文件位于独立私有前缀 `yxshop/technical-chat/consultations/`，RAM权限须覆盖该前缀的上传、读取和删除；不要对聊天前缀套用签名成品的短期到期规则。附件不落本地磁盘，不扣工具积分。

若反向代理限制上传体积，请允许至少21MB（例如 Nginx `client_max_body_size 21m;`），并确保上传与文件读取请求的代理超时足够；本轮未修改服务器Nginx。应用仍独立校验实际接收体积，不只依赖请求头。

## 数据与权限

图片/文件随消息上传到OSS，校验后提交消息和会话时间事务。事务确认失败时清理本次新文件；提交响应丢失先读回，避免删除已经保存消息的附件。无法确认的私有孤立对象保留待人工核对。

附件通过商城的鉴权接口读取：客户限本人会话，技术人员限被分配的会话，管理端要求在线咨询管理权限。身份参数本身不赋权。用户需使用有效的签名登录会话；旧格式登录会话可重新登录后使用附件。

安全识别的PNG、JPG、GIF、WebP内容支持图片展示；其他文件以下载附件返回，HTML/SVG不作为图片执行。可下载不代表文件经过病毒扫描，平台不执行附件。响应采用私有禁止缓存和禁止内容嗅探策略。

自动化检查使用内存SQLite及模拟OSS，不访问真实业务库或Bucket；真实网络、反向代理限制与页面交互由部署后验收。
