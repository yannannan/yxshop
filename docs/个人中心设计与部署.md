## 账号和积分

- 身份以签名 HttpOnly 商城会话和 `users.status / permission_type` 为准；不使用 localStorage 手机号授予身份或权限。
- 顶部显示头像、昵称和真实剩余积分，账户菜单集中提供个人中心、积分、订单、工具记录、地址、资料及退出。
- 管理员、技术人员入口只根据服务端角色显示，原后台接口权限校验不变。
- 登录后支持返回当前站内页面，拒绝外站、协议相对地址和后台 / API 返回地址。
- 登录、退出、资料保存、印章成功制作、视频任务完成、积分读取及充值核验后刷新账户信息；窗口重新获得焦点也可刷新。
- 多个控件共享请求。其他标签页的账户变更通过不包含个人数据的事件通知；迟到旧请求不能覆盖新身份。个人中心的记录、积分内容和地址在切换账号时隔离。
- 积分读取失败显示“暂不可用”，不将失败或未知值显示成 0。未登录、读取中、失败、记录为空分别展示。

## 资料保存与存储

- 新表 `yxshop_user_profiles` 按既有用户 ID 保存昵称、头像、头像摘要和时间，不修改登录手机号、用户权限或积分。
- 昵称最多 32 个字符，联系邮箱沿用当前商城 `users.email` 联系 / 订单通知规则；没有新增邮箱认证或手机号换绑流程。
- 选头像只生成当前表单预览；取消不保存。点击唯一“保存资料”按钮后，昵称、头像和邮箱在同一事务提交；失败回滚并保留表单以便重试。
- 客户端读取 PNG / JPG / WebP 后缩小至最长 512 像素并生成 JPEG；服务端只接受 PNG / JPEG，校验大小、文件头与尺寸，不接受 SVG / 外部图片地址。
- 头像以不超过 1MB 的图片数据存储在 MySQL 资料表，使用 `/api/account/avatar` 鉴权读取。没有新增本地上传副本，也不要求 OSS 密钥。替换头像不会积累孤立文件，迁移数据库即可同时迁移头像。
- 默认头像为项目内静态资源 `public/account/default-avatar.png`。已有账号在未编辑资料前显示默认头像及手机号末四位昵称，无需重新注册。

工具记录聚合现有服务端已保存的数据，不包含未曾入库的历史匿名 / 免费印章成品；不能回填当时未保存的记录。视频下载保留当前 OSS 长期保存或旧本地有效期规则，个人中心不延长旧文件寿命。

## 上线顺序

1. 备份业务数据库，在实际应用连接的库执行 `sql/09_account_center_20261025.sql`。此文件只新增资料表，可重复执行。积分及工具模块继续使用既有 06 / 07 / 08 等结构。
2. 将完整代码提交 / 推送到服务器实际跟踪的发布分支。
3. 在服务器项目目录运行 `bash upgrade.sh`。它仍按原策略安装 JS 依赖、仅检查视频依赖、构建并启动；没有修改升级或迁移脚本，没有新增系统引擎安装步骤。
4. 用现有账号登录，进入“个人中心”验收。

助手没有执行真实 SQL 或连接业务数据库。`upgrade.sh` 不会自动执行此 SQL。未执行 09 时仍可读取原账户与积分，资料编辑会明确提示初始化；记录模块缺表单独提示，真实查询错误不会伪装成空列表。

## 验收重点

1. 普通用户、管理员、技术人员在首页和各业务页看到一致的本人头像 / 昵称 / 剩余积分和对应专属入口。
2. 上传头像、修改昵称后，取消不改变资料；保存成功后顶部同步，失败后可重试。
3. 充值由管理员核验后到账；工具成功处理后扣分；顶部余额跟随真实业务更新，重复查看不另扣分。
4. 订单与工具记录只显示本人数据；切换筛选和分页后能打开正确的原订单或成品。
5. 地址增删改、原购物 / 技术服务下单与收银台流程仍正常。
6. 退出、跨标签页退出及切换账号后不沿用旧账号个人中心数据；手机宽度下菜单可操作，表格可横向滚动。

代码层检查使用隔离数据库、请求和交互模拟；生产页面验证直接调用构建包处理器，不启动端口或浏览器。用户既定约定为本地运行与浏览器验收由用户负责，因此没有声称视觉对比或真实生产业务已经验收通过。项目既有 20 处 TypeScript 问题不属于本轮，新个人中心没有增加类型错误。
