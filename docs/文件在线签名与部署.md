# 文件在线签名与部署

工具服务入口为 `/tools/document-signature.html`。支持简体中文和英文。

工具服务列表另提供「手印制作」独立入口 `/tools/handprint-maker.html`，默认打开手印制作工作区。它与文件在线签名共用手印库、制作记录及套餐，积分价格读取「文件在线签名 → 手印制作」模块配置，无需再创建产品或执行新的 SQL。

## 使用流程

- **制作签名**支持鼠标、触屏手写或导入 PNG、JPG、WebP。保存时裁掉透明空边，生成个人签名库中的 PNG。签名库可保存 30 个签名，可选用或删除。
- **手印制作**支持上传或手机拍摄手印、指印照片，框选区域后按红色印迹或深色笔迹提取，调整颜色和强度。也可生成随机装饰性指印图案。保存透明 PNG 至本人手印库，保留制作时间、积分和历史记录；可下载或直接用于签署，每人最多保留 30 个有效手印。删除素材保留历史元数据与已签署成品。
- 点击「保存手印」后弹窗输入名称，确认才提交保存并结算；取消或按 Escape 不保存、不扣费。相同图案与名称重复确认沿用原任务，避免断线重试重复收费。
- **签署文件**支持 PDF、普通 DOCX、PNG、JPG、WebP。选择已保存的签名后，可在任意预览页放置，拖动位置或调整尺寸。一份文件最多放置 30 处。PDF 保持原页数、页面旋转与裁剪。DOCX 先转换为 PDF 再预览，成品保持该预览的分页。图片按面板显示的预览尺寸输出 PNG，最大 200 万像素。
- 文件预览支持 25%～400% 缩放，可使用加减按钮、滑条或「适应窗口」。放大后通过横纵滚动条查看；手机支持双指缩放、单指拖动查看，轻点页面放置素材，按住已有签名或印章可移动。缩放仅调整预览，导出使用原文件坐标与尺寸，缩放不扣积分。
- 签署素材包括签名、印章、手印三个选项，支持混合放置、拖动及 Delete 移除。左右面板在桌面等高，预览区填满可用高度；手机端上下排列。
- 点击页面上已放置的素材后，右侧可用滑条或数值输入调整 −180°～180°，并提供向左 / 向右 90°及角度复位。每个放置项独立绕中心旋转，拖动、改变尺寸与旋转均约束在页面内。PDF、转换后的 Word 和图片成品使用与预览一致的角度；修改角度后需重新生成成品，调节预览本身不扣积分。
- 单次上传最多 12 MB，文档最多 100 页，签署成品最多 20 MB。最近成品在 7 天内可下载。此工具生成可视签名。

## 积分配置

首次启用时，制作签名为 10 积分，签署文件为 20 积分。管理员打开「工具服务 → 文件在线签名 → 积分配置」，分别配置制作签名、签署文件和手印制作价格。留空时继承工具默认价格。已有有效套餐按商城通用权益规则优先使用。

手印制作新增独立积分项 `handprint`，未单独配置时继承工具默认价格。上传提取与随机生成使用同一制作价格，预览免费，保存成功才结算。下载和选用已有手印不再扣制作积分；生成签署文件仍按签署价格结算。同一制作任务重试不会重复扣积分。

签名保存与积分写入在同一数据库事务中完成。文件签署先上传并校验私有 OSS 成品，再在同一事务中写入成品记录及积分。失败时回滚，同一任务可重试。下载已生成的同一成品不会再次扣积分。

## 部署

1. 备份应用数据库并执行 [13 号增量 SQL](../sql/13_document_signature_20261109.sql)。前置为 02、03、06、07 号。已有文件签名工具的自定义价格与内容会保留。后台可检查其启用状态与模块价格。
   已有文件签名的环境本次只需额外执行 [14 号手印增量 SQL](../sql/14_document_handprints_20261111.sql)，仅创建 `document_handprints` 表，可重复执行。未执行时原签名、印章及签署可继续使用，手印面板会提示管理员初始化。初始化脚本不会替代这份增量 SQL。
2. 配置签名 OSS。所有 `SIGNATURE_OSS_BUCKET`、`SIGNATURE_OSS_REGION`、`SIGNATURE_OSS_ACCESS_KEY_ID`、`SIGNATURE_OSS_ACCESS_KEY_SECRET`、`SIGNATURE_OSS_STS_TOKEN` 留空时，使用现有 `VIDEO_OSS_*` 的存储连接。单独配置时填写整组签名参数，STS 仅临时凭据需要。授权 `yxshop/document-signatures/` 目录的上传、私有 ACL、读取及删除权限。可通过 `SIGNATURE_OSS_INTERNAL_UPLOAD=1` 使用同地域内网上传。
3. 给 OSS 的 `yxshop/document-signatures/` 单独添加 8 天过期清理规则，回收成品和中断时残留的上传。应用下载有效期为 7 天，每次下载由商城核对账号后签发 5 分钟公网 HTTPS 地址。原文件不会长期保存，签名模板保存在应用数据库。
4. DOCX 默认启用。若现有 `.env.mysql` 显式关闭了转换，将 `SIGNATURE_WORD_ENABLED` 设置为 `1`。系统转换程序可用时走原有沙箱，依赖缺失或系统转换失败时使用随项目安装的 LibreOffice WASM。内置包解包约 242 MiB，转换按需启动独立进程，单进程同时处理一个内置转换任务。
5. 同步完整代码和锁文件，再执行 `bash upgrade.sh`。新服务器使用 `migration_upgrade.sh` 时会执行文件签名准备检查。Nginx 上传限制需允许 12 MB 文件加表单开销，代理等待时间应覆盖 Word 转换及 OSS 上传。

PDF 预览资源随应用提供。Word 分页受服务器字体影响，以签署前的 PDF 预览为准。支持普通 DOCX，含宏、ActiveX 或嵌入对象的文件请先另存为 PDF。

### DOCX 转换检查

Linux 上在项目目录执行第一条命令查看转换开关和可用引擎。第二条可用测试文档运行实际转换并检查生成的 PDF。

```bash
node --env-file=.env.mysql scripts/check-signature-word.mjs
node --env-file=.env.mysql scripts/check-signature-word.mjs /path/to/test.docx
```

配置通过后，重启读取 `.env.mysql` 的商城进程。

### Windows 本地开发

Windows 本地在项目目录执行 `pnpm install --frozen-lockfile`，然后重启 `pnpm dev`。浏览器端直接选择 DOCX，看到转换后的 PDF 即可定位签名。默认可用内置转换器，已配置且依赖齐全的 WSL 2 可优先承担转换。

如需启用 WSL 系统转换，用 `wsl.exe --list --verbose` 确认发行版名称和版本。以下命令以本机的 `Ubuntu-22.04` 为例，在该发行版安装无界面的 Writer、沙箱及中文字体。

```powershell
wsl.exe -d Ubuntu-22.04 -u root --exec apt-get update
wsl.exe -d Ubuntu-22.04 -u root --exec apt-get install -y --no-install-recommends libreoffice-writer-nogui bubblewrap fonts-noto-cjk
```

在项目 `.env.local` 设置以下参数。

```dotenv
SIGNATURE_WORD_ENABLED=1
SIGNATURE_WORD_WSL_DISTRO=Ubuntu-22.04
```

执行下面的自检，通过后重启 `pnpm dev`。也可在自检命令后传入本地测试 DOCX 的路径，验证实际转换与 PDF 页数。线上 Linux 继续读取 `.env.mysql`，客户端使用 Windows 浏览器访问时直接由服务器转换。

```powershell
node --env-file=.env.local scripts/check-signature-word.mjs
```

## 验收

部署后用测试账号保存签名，然后分别签署旋转的多页 PDF、一张图片和一份 DOCX。核对预览位置、最终文件和两次积分流水，重复下载检查余额。使用不同账号打开下载地址应被拒绝。线上 OSS 与 Linux Word 沙箱需要在部署环境验收。
